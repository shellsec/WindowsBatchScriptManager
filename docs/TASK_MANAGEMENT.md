# 任务管理增强（1.2.0）

主菜单新增 **任务增强 / Task tools**，新功能无需额外安装依赖。

## 模板与导入

- **从模板创建**：Python、Node.js、PowerShell、批处理。Python 默认设置 `PYTHONUNBUFFERED=1`；解释器、脚本路径和参数可继续修改。确认保存才创建，不自动执行。
- **批量导入文件夹**：选择或拖入文件夹，后台扫描后预览。双击行、空格键或“切换勾选”按钮选择脚本；可切换递归扫描。按绝对路径去重，已存在项不重复添加，跳过 `.git`、虚拟环境、`node_modules`、`build`、`dist` 等目录。

## 运行环境

选择任务后使用 **选择任务运行环境**，或在任务编辑窗口使用 **选择环境**。支持系统 PATH 的 Python、Node、PowerShell，项目 `.venv`/`venv`，Conda 已有环境，常见 NVM 版本目录；也可浏览解释器文件。

Conda 选择结果包含环境目录，运行时设置 `CONDA_PREFIX` 与对应 PATH；不会安装环境。自定义环境变量可覆盖自动值。未发现 Conda 时，可手动浏览解释器；如需 Conda 的完整环境变量，请从发现列表选择 Conda 项。

## 并发与队列

**并发上限**设置同时运行数量，`0` 表示不限；降低上限不会终止已运行的任务。手动、定时、批量、启动自动执行、自动重启和后续任务共用 GUI 队列。同一任务运行或排队时去重。

任务列表显示“排队中”；**查看/取消排队**可取消待启动项，停止任务也会取消该项排队。等待依赖的任务不占槽位；已有依赖表示“依赖必须正在运行”，请为依赖服务和任务预留足够槽位。

## 成功码与后续任务

选择任务后打开 **运行规则与后续任务**：

1. 成功退出码输入逗号分隔的整数，例如 `0,2`；默认 `0`。
2. 勾选成功后和失败后执行的任务，可多选。
3. 保存时检查缺失引用和循环。完成后运行的下游不能同时要求已完成的上游保持运行；流水线关系请用“成功后执行”，服务前置条件用原有“依赖”。

历史、退出结果和退出码异常通知采用同一成功规则；手动停止、取消和无法取得退出码不会触发后续任务。原有“快速退出通知”仍单独生效，可在通知设置中关闭。

开启保活时，失败优先自动重启，达到崩溃循环保护阈值后才触发失败分支；正常完成保留原来的保活行为。普通流水线任务建议关闭保活。

**队列和任务串联由打开的 GUI 管理**，关闭工具取消未启动的排队项；原本运行的子进程遵循旧的退出策略。CLI/API 独立启动不会在命令退出后继续管理整条流水线。

## 配置与命令行

任务 ID 持久保存，删除或排序不改变其他 ID；旁边的 `任务配置文件名.ids.json` 记录已分配 ID 的上限，备份迁移时建议一起保留。旧配置自动迁移。导出、合并导入保留新字段，并重映射导入任务间的引用。

```powershell
python main.py --update 1 --success-exit-codes "0,2" --on-success "2,3" --on-failure "4"
python main.py --update 1 --on-success "" --on-failure ""
```

API 的 `/add`、`/update` 支持 `success_exit_codes`、`on_success`、`on_failure` 查询参数（逗号分隔），CLI/API 修改其他字段会保留这些设置。

## 验证

运行 `.venv-build/Scripts/python.exe -m unittest discover -s tests -v`。测试使用临时配置与临时子进程，不执行用户已有任务。
